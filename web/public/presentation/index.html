Today vs. Lanekeeper

Cities sweep bike lanes with a driver, a schedule and a web form.

New York's Sanitation Department sweeps protected lanes with small staffed machines, aiming for every lane once a week. Glass that lands the night after a pass waits for the next one unless someone reports it to 311.

A driverOne operator per machine

Every staffed mini-sweeper needs a person in the cab for the whole shift.

A scheduleOnce a week per lane

Routes run on a fixed timetable whether or not glass has landed.

A web form311 reports in between

Riders file a request; in 2025 the median broken-glass report took 22 hours to close.

The machine

Narrower than the lane. Lower than a pedal.

It has to fit inside a protected lane with room for an early rider to pass, so the design envelope is 0.8 m wide and 0.55 m tall. The camera sits low and looks forward and down, which is the angle that makes glass flash.

Footprint
0.80 × 1.30 × 0.55 m, rides inside the lane, leaves ~0.7 m to pass
Pickup
Twin side brooms feed a center roller and vacuum into a sealed glass hopper (rigid, puncture-proof liner)
Speed
6 km/h sweeping, 12 km/h transit, stops and yields to any rider
Range
One 2-hour window, ~10–12 km of lane, returns to a depot dock to charge by day
Eyes
Low forward RGB pair + strobe with crossed polarizers, rear camera for after-photos
Position
RTK GNSS + wheel odometry, map-matched to 25 m lane cells
Link
LTE/5G to Supabase and the Gemini API; works offline and syncs at the dock

How it sees glass

Fast reflexes on board. Judgment from Gemini.

A sweeper moving at walking pace can't wait on a round trip to the cloud before it brushes. So it splits the job: a small on-board detector reacts in real time, and Google DeepMind's Gemini Robotics-ER model verifies, points, counts and decides whether a second pass is needed.

01 · ON BOARD

Flash and flag

The strobe fires in alternating polarized frames. Glass returns a hard specular flash that asphalt, paint and leaves don't. A compact edge detector flags candidate patches and drops the brooms immediately.

~30 fps · <50 ms
02 · GEMINI ROBOTICS-ER

Verify and point

Flagged frames go to gemini-robotics-er-2-preview with a prompt to point at every shard, returning [y, x] points normalized 0–1000 plus a shard estimate. It rules out ice, clear plastic, reflectors and wet leaves.

per flagged frame · async
03 · PLAN

Sweep the spread

Points become a sweep path: the robot shifts its line toward the cluster, slows, and widens the brooms. Through function calling, the model can also call request_second_pass or skip_cell when a parked car blocks the lane.

plan per cluster
04 · PROVE

After-photo, then log

The rear camera re-checks the patch. If Gemini finds nothing left, a remediation row is written to Supabase with time, cell and shard count, and the live map updates for every subscribed app.

1 write per cleared spot
Model note

As of October 2026, Google lists gemini-robotics-er-2-preview and a streaming variant for live video. The earlier gemini-robotics-er-1.6-preview was deprecated on Aug 31, 2026, so the build should target ER 2. Pin the model ID in config and re-check before field trials; preview IDs change.

Map data strategy

Every lane, cut into 25-meter cells.

Glass is a point problem, but riders and routing engines think in streets. The fix is a stable middle unit: the lane cell. Everything the sweeper sees, clears or misses is keyed to one.

L1

City base layer

Import NYC DOT's bike routes from NYC Open Data (dataset mzxg-pwib, GeoJSON) into PostGIS weekly. Keep the DOT segment ID and facility type so protected lanes, painted lanes and greenways can be planned differently.

L2

Lane cells

Split each segment into 25 m pieces with ST_LineSubstring and give them stable IDs like MN-1AV-0412. When DOT redraws a segment, cells are re-matched by geometry, so history survives.

L3

City context

Join signals that predict glass: 311 street-condition complaints, Saturday and Friday nights, nearby bars and venues, DOT street closures and construction. These raise a cell's score before the robot has ever seen it.

L4

Sweeper observations

Detections and remediations as points, snapped to the nearest cell with ST_ClosestPoint. Raw frames stay in storage with faces and plates blurred on board.

H(cell) = Σ shards·e−Δt/3 nights + 0.6·recur₃₀ + context

Each evening the planner ranks cells by hazard H and builds the night's route: the highest-hazard cells on commuter corridors first, finished before 6 a.m., within one battery.

Supabase

One Postgres database holds the city's glass.

Supabase gives the project Postgres with PostGIS for geometry, Storage for frames, Edge Functions to call Gemini with the key kept server-side, Realtime to push every cleared spot to apps, and row-level security to separate public data from fleet data.

-- L1: NYC DOT bike routes (Open Data mzxg-pwib)
create table lane_segments (
  id          bigint primary key,
  street      text,
  facility    text,     -- protected, painted, greenway
  borough     text,
  geom        geography(LineString, 4326) not null,
  source_ver  date not null
);

-- L2: stable 25 m cells
create table lane_cells (
  id          text primary key,   -- MN-1AV-0412
  segment_id  bigint references lane_segments,
  seq         int,
  geom        geography(LineString, 4326) not null
);
create index on lane_cells using gist (geom);

create table sweepers (id text primary key, name text, depot text);
create table runs (
  id           uuid primary key default gen_random_uuid(),
  sweeper_id   text references sweepers,
  started_at   timestamptz, ended_at timestamptz,
  planned_cells text[]
);

-- L4: what the robot saw
create table detections (
  id          uuid primary key default gen_random_uuid(),
  run_id      uuid references runs,
  cell_id     text references lane_cells,
  seen_at     timestamptz not null,
  location    geography(Point, 4326) not null,
  edge_conf   real,
  er_verdict  text check (er_verdict in ('glass','not_glass','unsure')),
  er_point    int[],    -- [y, x] normalized 0-1000
  est_shards  int,
  frame_path  text      -- Storage, blurred on board
);

-- what it fixed
create table remediations (
  id            uuid primary key default gen_random_uuid(),
  detection_id  uuid references detections,
  cell_id       text references lane_cells,
  cleared_at    timestamptz not null,
  passes        int default 1,
  confirmed     boolean,
  after_path    text
);

-- push every clear to apps and partner maps
alter publication supabase_realtime add table remediations;

-- hazard ranking for tomorrow night's route
create materialized view cell_hazard as
select c.id,
  coalesce(sum(d.est_shards * exp(
    -extract(epoch from now() - d.seen_at) / (3*86400))), 0) as decayed,
  count(d.id) filter (where d.seen_at > now() - interval '30 days') as recur_30d
from lane_cells c
left join detections d
  on d.cell_id = c.id and d.er_verdict = 'glass'
group by c.id;

-- public can read clears; only the fleet's service role writes
alter table remediations enable row level security;
create policy "public reads clears" on remediations
  for select using (true);
// supabase/functions/verify-glass/index.ts
import { GoogleGenAI } from "npm:@google/genai";
import { createClient } from "npm:@supabase/supabase-js@2";

const ai = new GoogleGenAI({ apiKey: Deno.env.get("GEMINI_API_KEY")! });
const db = createClient(
  Deno.env.get("SUPABASE_URL")!,
  Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")!
);

const PROMPT = `Ground-level frame from a bike-lane sweeper.
Point to every piece of broken glass. Ignore ice, clear plastic,
road reflectors and wet leaves. Answer as JSON:
[{"point": [y, x], "label": "broken_glass", "shards": n}]
Points are [y, x] normalized to 0-1000.`;

Deno.serve(async (req) => {
  const { detectionId, frameB64 } = await req.json();

  const res = await ai.models.generateContent({
    model: "gemini-robotics-er-2-preview",
    contents: [{ role: "user", parts: [
      { inlineData: { mimeType: "image/jpeg", data: frameB64 } },
      { text: PROMPT },
    ]}],
    config: { responseMimeType: "application/json" },
  });

  const pts = JSON.parse(res.text ?? "[]");
  await db.from("detections").update({
    er_verdict: pts.length ? "glass" : "not_glass",
    er_point:   pts[0]?.point ?? null,
    est_shards: pts.reduce((n, p) => n + (p.shards ?? 1), 0),
  }).eq("id", detectionId);

  return Response.json({ points: pts });
});

Privacy by default. Faces and license plates are blurred on the robot before any frame leaves it. Public feeds carry only cell, time and counts. Raw frames are kept 30 days for model quality review, then deleted.

Riders report glass

See glass? Snap it and text GLASS.

No app to install. A rider texts a photo to GLASS (45277) or sends it on WhatsApp. Gemini checks the photo, the location comes from the photo or a quick reply, and the spot joins tonight's sweep queue.

  1. 1

    Photo arrives

    Twilio receives the MMS or WhatsApp message and calls the sms-glass function, which rejects anything without a valid Twilio signature.

  2. 2

    Find the spot

    Location comes from the photo's GPS metadata when it survived the trip. If not, the reply asks for a WhatsApp location pin or the nearest cross streets, matched with NYC Planning's GeoSearch.

  3. 3

    Gemini checks it

    Gemini Robotics-ER confirms glass, counts pieces, rates severity and notes whether it's on a bike lane, so litter and ice don't fill the queue.

  4. 4

    Queue the sweep

    The report snaps to the nearest 25 m lane cell, raises that cell's hazard score, and is queued for the next 4–6 a.m. run. Phone numbers are stored only as salted hashes.

After every run

Anyone can scan and see what was swept.

When a sweeper finishes, the database writes a public report for that run: when it ran, how many glass spots it cleared, how many shards, and where. A QR code on lane signs, the sweeper's back panel and the depot door opens it on any phone.

  1. 1Run ends. The sweeper sets runs.ended_at when it docks.
  2. 2Report builds itself. A database trigger writes a row to run_reports with the run's cleanups.
  3. 3Riders scan. The QR opens a phone-first report page that shows cell, time and count, never camera frames.

The pilot ask

Two robots, two avenues, 90 days, no cost to the city.

Lanekeeper sweeps the 1st and 2nd Ave protected lanes from E 14th St to E 125th St every night, with an attendant on every run, on top of DSNY's weekly pass. Robots sweep only after two weeks of detect-only runs prove 90% accuracy.
